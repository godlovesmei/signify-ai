# Internationalization Guide

SignifyAI uses `next-intl` with the Next.js App Router. Indonesian is the default locale and stays unprefixed. English uses the `/en` prefix.

## Locale Rules

- Supported locales live in `i18n/config.ts`.
- `id` is the default locale and should render at `/`, `/translate`, `/research`, and other unprefixed routes.
- `en` renders at `/en`, `/en/translate`, `/en/research`, and other prefixed routes.
- `/id/*` is handled as a canonical redirect to the unprefixed Indonesian URL.
- Browser locale detection is disabled so canonical URLs remain stable for SEO.

## Adding Copy

1. Add the new key to `messages/id.json`.
2. Add the same key path to `messages/en.json`.
3. Read it from a focused namespace with `useTranslations`, `getTranslations`, or `t.raw` for structured arrays.
4. Keep domain terms stable. For example, `BISINDO` should remain a sign-language domain label, not a UI locale.
5. Run `pnpm test` to execute the message parity test.

Prefer namespaces by surface:

- `common` for repeated buttons, states, and labels.
- `navigation` for navbar, footer, sidebar, and mobile nav.
- `landing` for the home page.
- `docs` for public documentation pages.
- `workspace` for translate, practice, reference, history, and profile.
- `auth` for login and auth guard copy.
- `settings` for drawer preferences.
- `seo` for metadata, OpenGraph, and JSON-LD text.

## Adding A Page

1. Create the route under `app/[locale]/...`.
2. Use locale-aware navigation from `@/i18n/navigation` for UI links and router calls.
3. For server pages, call `setRequestLocale(locale)` in the nearest layout when applicable.
4. For protected workspace pages, keep them under the workspace route group so they inherit `noindex`.
5. If the route is public and indexable, add it to `PUBLIC_ROUTES` in `i18n/metadata.ts` so sitemap and alternates include it.

## Adding Metadata

1. Add localized SEO copy under `seo.pages.<pageName>` in both message files.
2. Implement `generateMetadata` with `getTranslations({ locale, namespace: "seo" })`.
3. Return `buildPageMetadata({ locale, pathname, title, description, keywords, imageAlt })`.
4. Keep `pathname` unprefixed. The helper builds canonical and `alternates.languages`.
5. Use `index: false` for protected, account, demo, or internal pages.

## Adding A Locale

1. Add the BCP-47 locale code to `locales` in `i18n/config.ts`.
2. Add a `localeConfigs` entry for `htmlLang`, `intlLocale`, OpenGraph locale, and TTS language.
3. Create `messages/<locale>.json` with the same key structure as `id.json`.
4. Confirm routing behavior in `i18n/routing.ts`, especially whether the new locale needs a prefix.
5. Update tests for path builders, auth redirects, sitemap alternates, and message parity.

## Verification

Run these before merging i18n changes:

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm test:e2e
```

For copy-heavy changes, also spot-check `/`, `/research`, `/terms-condition`, `/en`, `/en/research`, and `/en/terms-condition`.
